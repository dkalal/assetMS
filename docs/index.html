Core features

Multi-tenancy

Fine-grained tenant isolation with shared or isolated schemas, per-tenant configuration, usage quotas, and secure data partitioning.

Asset lifecycle

Track procurement, assignments, maintenance, depreciation, and retirement with event-driven workflows and scheduled rules.

Security & RBAC

Role-based access control, SSO/OIDC integration, permission boundaries, encryption at rest and in transit, and audit logs for every change.

Integrations

Webhooks, webhook signing, message buses (Kafka/RabbitMQ), CMDB sync, ITSM connectors, and CI/CD-friendly APIs.

Architecture & design principles

Built for scale, maintainability and operational excellence.

Modular services

Small, focused microservices (or modular monolith by choice) expose clear API contracts. Each module has its own tests, CI, and deployment pipelines.

Stateless compute

Services are stateless where possible; state is stored in purpose-built stores (SQL for relational, object stores for files, caches for hot reads).

Event-driven

Use pub/sub for decoupling, reliability, and asynchronous processing (background jobs, notifications, audit publishing).

Multi-tenancy patterns

Support both shared-schema (with tenant_id) and isolated-schema strategies. Provide migration tooling and tenant onboarding APIs.

Operational notes: design for graceful degradation, health checks, metrics (Prometheus), tracing (OpenTelemetry), and robust backups.

Security & compliance

  • Least-privilege RBAC and audit trails for all mutating operations.
  • OIDC/SAML SSO, SCIM for user provisioning, and MFA recommendations for admins.
  • Encryption using KMS for secrets and keys, TLS everywhere, and strict CORS & CSP policies.
  • Automated vulnerability scanning in CI and dependency management.

Get started

Run locally

git clone https://github.com/dkalal/assetMS.git
cd assetMS
# start services with Docker Compose (example)
docker compose up --build

Deployment

Deploy as containers to Kubernetes with horizontal autoscaling. Use managed databases and object storage for reliability. Provide a Helm chart or k8s manifests in deploy/.
